# 故障恢复与继续执行

[English](../en/execution-recovery.md) · [使用说明](./usage.md) · [已审核界面](./recovery-proposal.md)

**状态：宿主恢复与已审核恢复界面均已实现。** 本文描述开发源码，不表示已经安装或发布。修复故障后点击带播放图标的**继续执行**，也适用于 VS Code 重载后。提示显示 Worker、Reviewer 或系统、阶段、操作和恢复次数；不可恢复时给出原因，未知进程允许重新检查但不能绕过清理。

## 恢复范围

模型或系统故障会保存出错角色、阶段及操作。恢复保持同一个运行 ID、目录、方案和工作轮次，读取当前任务绑定的连接、密钥和模型；任务要求、角色指令、命令预设及轮次上限保持该运行的快照。Reviewer 仍负责独立验证，Worker 负责修改源码。准备工作由宿主执行，不能把宿主错误当成某个模型的失败。

关闭或重载扩展后，未结束运行标记为 `interrupted`，不会自动启动模型或命令。仅任务最新且未被取代的运行可恢复；主动停止、次数上限、缺少恢复点的旧记录不能通过恢复绕过限制。重新执行创建新运行；删除任务同时删除恢复文件。故障期间发送的消息留待恢复，Reviewer 先答疑或修订方案，再接回原执行位置。

恢复的是角色阶段和已记录的操作边界，不是操作系统进程内部现场。文件修改保持原样。任意 shell 命令不具备事务或“只发生一次”保证；执行器不重放已确认完成的同一操作 ID，模型发出的新调用仍可能产生相同副作用。

## 持久化与上下文

`src/execution/recovery.ts` 在扩展工作区存储的 `recovery/` 下维护版本 1 顺序日志、当前检查点和上一检查点。记录有递增序号与哈希链；操作意图先刷盘，再执行，结果刷盘后才能推进。状态快照经临时文件刷盘、原子替换；Unix 同步目录。完整顺序日志是恢复依据，快照不能掩盖后续操作；上限为 64 MiB。当前快照损坏但完整日志可验证时可以重建；中间记录损坏、冲突索引或不支持的数据结构阻止恢复。末尾不完整行仅在显式恢复后写入时移除，已开始但缺少结果的操作按未知处理。

工具分为尚未开始、已开始、成功、失败、结果未知。操作已经修改文件但完成记录尚未落盘时，仍有崩溃窗口，不能声称该操作未执行。方案、成果、验收和答复的应用位置与状态一起持久化；公开聊天投影有去重标识并能从恢复数据补齐，不依赖最近 80 条事件。

正常暂停保留内存历史。系统恢复重建公开上下文，包含方案、成果、当前证据、未确认操作和最近操作摘要；旧记录可用只读 `read_operation` 分页读取，命令完整输出仍通过 `read_command_output` 读取。跨协议恢复不拼接原始协议消息。API 密钥、原始环境变量、私有推理及加密推理不进入恢复文件或公开界面；现有 512 KiB 请求上下文限制仍有效。

## 错误与重试

命令退出非零、命令不存在、普通文件工具错误仍作为工具结果返回模型。命令超时或输出超限后必须确认进程清理；清理失败阻止继续。

模型请求仅在尚未收到有效流事件时，对临时网络问题及 HTTP 408、425、普通 429、500、502、503、504 最多请求三次。默认等待 1 秒、2 秒，遵循合法的 `Retry-After`，总时间包含等待且共用 120 秒预算；等待超出预算时不提前重试。认证、额度、证书、参数或协议问题不自动重试。错误正文最多读取 8 KiB 用于分类，不转发原始正文。重试等待可取消，记录尝试次数；不重放工具或自动切换模型。收到有效流事件后中断时保留公开过程，等待手动恢复，不执行部分工具调用。

## 进程、代次与验证

恢复前重新校验目录绑定和信任、模型配置、环境、当前文件及成果指纹。命令保留进程创建身份；Unix 使用进程组，Windows 使用现有进程树查询与清理。无法证实进程已经停止或身份不充分时阻止恢复，也阻止新任务命令。Windows 祖先进程消失导致的归属不确定性保持保守处理，不以 `taskkill` 返回成功冒充清理完成。

每次恢复分配新代次，旧模型输出、工具回调和交接不能推进新状态。取消路径保存已发生的操作，清理确认后才允许新执行。用户主动停止与持久化失败分别归因，存储失败不伪装成用户停止。

成果发生变化时旧验收证据失效，Reviewer 必须要求重新验证或交给 Worker 修订；较新的失败不能被旧成功覆盖。恢复不额外增加正常工作轮次，也不清零已完成的角色调用和参数纠错次数。

测试覆盖与本机／CI 的实际运行结果见[开发日志](./development-log.md)。未运行的平台不视为已验证。
