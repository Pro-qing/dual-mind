## 旧运行器的环境与结果（历史记录）

环境为 Ubuntu 20.04.6 amd64、Node 24.22.3、Git 2.25.1、VS Code 1.141.0，使用现有桌面会话。本地检查按 1 GiB／60 秒、Electron 按 2 GiB／180 秒配置用户级 systemd 单元，禁止交换空间。该机器的混合 cgroup 挂载不满足生产命令运行器要求的 cgroup v2 内存及交换空间探测；设置单元属性不等于实际限制已验证。

| 验证                                          | 实际结果                                                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `npm run check`                               | 通过：22 项环境测试；108 项本地测试中 107 通过、1 项真实 systemd 测试未启用；类型、lint、格式、文档检查通过 |
| `npm test`，使用本机 VS Code                  | 2 项扩展宿主测试通过：命令与活动栏激活、真实 React Webview 渲染、标签复用与关闭后重开                       |
| `npm run test:ui`，使用本机 VS Code           | 界面、两轮阅读验收及重载中断恢复通过，生成 32 张截图；整体退出码 2，属于部分覆盖                            |
| 显式启用 `DUALMIND_TEST_SYSTEMD=1` 的命令测试 | 1 项实际失败，0 跳过：首次资源探测返回 `systemdLimits`，未继续运行命令限制与取消场景                        |

测试均使用临时仓库、隔离编辑器配置、本地模型模拟服务和测试密钥，没有读取个人 API 凭据或发起付费推理请求。

## 已覆盖行为

- 两种模型协议下 Reviewer 首先下发方案、Worker 自主执行与验证、Reviewer 验收未通过并下发下一轮方案，随后完成。
- 无预设命令启动、Worker 自主准备步骤、无命令阅读验收、旧自定义命令兼容及关闭后保留值。
- 结构化嵌套工具校验、角色越权拒绝、方案 ID 保持、失败／伪造／过期证据拒绝、较新失败覆盖旧成功；整轮未通过时也不能将缺少有效证据的单项标记通过。
- 暂停与反馈经过 Reviewer 更新方案、配置和角色固定、停止后的迟到 Worker 调用、成果变化、轮次上限、重启重新规划、Git 目录与分支绑定。
- 真实界面中的任务导航、中英文状态与错误、方案恢复、阅读验收未通过后下发新方案并在第二轮完成、重载中断且不重放调用、附加命令开关，以及实际窄 Webview 的单列方案布局。截图脚本先退出窗口最大化，尊重 VS Code 最小窗口宽度，再等待 Webview 实际尺寸与重排。

## 本地命令运行器复验（2026-11-20）

在同一 Ubuntu 20.04.6 amd64、Node 24.22.3、Git 2.25.1、VS Code 1.141.0 环境中复验，未修改系统 cgroup 配置。产品已移除 systemd/cgroup 探测和内存／交换空间配额；以下结果取代旧运行器未能完成的命令场景，旧失败记录保留。

| 验证              | 实际结果                                                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run check`   | 通过：22 项环境测试、117 项本地测试，零失败、零跳过；类型、lint、格式及文档检查通过                                                           |
| 真实命令测试      | 默认执行的 8 项测试全部通过：参数、目录、环境隔离、启动错误、非零退出、取消竞争、超时、输出超限、顽固子进程及父进程退出后的清理、终止失败报告 |
| `npm test`        | 本机 VS Code 中 2 项扩展宿主测试通过                                                                                                          |
| `npm run test:ui` | 退出码 0；43 张截图；命令闭环、双语错误、停止、三种 Git 策略、两轮阅读验收和重载恢复全部通过；`skipped: []`                                   |
| `npm run package` | 通过，生成 `release/dual-mind-0.0.3.vsix`，供手动安装                                                                                         |

真实 UI 发起 41 次本地模拟推理请求，覆盖 Chat Completions 和 Responses。命令实际在临时项目中运行；停止测试先读取命令写入的 PID，再确认对应进程退出。运行器测试用 PATH 中的失败桩确认不调用 `systemd-run` 或 `systemctl`。原 systemd 错误的中英文历史兼容也有测试。

首次综合检查被原有 60 秒外层预算中止，不计为通过；加入真实 10 秒超时与 3 秒强制清理测试后，综合检查预算调整为 120 秒并完整通过。其余本地批次仍为 60 秒，Electron 为 180 秒。验证外层仍申请 1 GiB／2 GiB、禁用交换空间；混合 cgroup 下这些属性不证明实际内存限制生效，也不再影响产品运行器。真实 UI 复验中修正了窗口恢复尺寸竞争、语言切换异步等待及带轮次的停止状态断言。

本次验证限于上述 Linux 桌面组合；未重新运行远端 CI、最低 VS Code 1.100.0 或其他平台，也未使用真实外部模型服务。命令按当前用户权限运行，清理覆盖同一进程组，不承诺追踪主动脱离该组的后台服务。此次不自动安装 VSIX，也不公开发布。
