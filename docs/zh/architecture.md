## 页面导航与结构化错误

`src/shared/navigation.ts` 定义 `home`、携带 `taskId` 的 `task` 以及携带 `returnTo` 的设置页面。导航通过 Webview state 保存，创建使用保存结果返回的任务 ID；页面恢复会校验任务仍存在。旧 `workbench` 状态回到主页。主页与详情复用任务表单，原生新建请求可在设置页打开表单并在取消后保留原页面。

`src/shared/errors.ts` 定义错误标识、参数、原始详情和双语格式化。错误在产生处标记类型；宿主在发送或保存前脱敏。执行摘要与事件保留结构化错误，UI 在显示时按当前语言格式化；VS Code 原生通知使用相同格式。旧文本记录继续可读。版本 1 中的 `status: 'draft'` 仅作为存储兼容字段，界面使用“待执行”或运行记录状态。

## 已实现的本地工作台

`dualMind.openWorkbench` 创建或定位一个 React Webview 面板，面板渲染宿主快照后命令才完成；序列化恢复逻辑在窗口重载后重新打开面板。`dualMind.showStatus` 保留为本地化的就绪提示。命令、监听和面板随扩展生命周期释放。

宿主拥有本地状态并校验所有输入操作；React 管理页面导航、表单缓冲、弹窗和独立的只读示例预览。界面不发起模型请求，创建成功后进入该任务详情，显示“待执行”，由用户手动开始。

## 状态归属

| 状态                                               | 存储与行为                                                                              |
| -------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 任务与选中任务                                     | `ExtensionContext.workspaceState`，键为 `dualMind.local.workspace.v1`，要求已打开工作区 |
| 连接、模型默认值、自定义角色和内置角色分语言覆盖值 | `ExtensionContext.globalState`，键为 `dualMind.local.global.v1`                         |
| API 密钥                                           | `ExtensionContext.secrets`，以连接 ID 关联，不进入界面快照                              |
| 语言选择                                           | 用户设置 `dualMind.language`：`auto`、`zh-CN`、`en`                                     |
| 选中页面                                           | Webview 状态，重载后可恢复                                                              |
| 未保存表单、弹窗和示例预览                         | React 内存；示例不会进入任务存储                                                        |

存储层在同一宿主内串行处理写入，避免快速操作丢失状态；检查已存数据的版本和结构，发现不受支持的数据时报告错误，不覆盖原数据。持久化成功后宿主确认操作，并返回新快照；保存失败时保留表单供重试。

创建任务会保存一个 Reviewer 角色的名称、用途、指令和语言快照，编辑已有任务仍保留该快照。内置角色覆盖值按语言独立保存，自定义内容标记为 `original`，不会自动翻译。Worker 始终是固定通用执行角色。删除角色不影响快照；删除连接会移除其密钥、清除对应默认值，并保留引用它的任务供重新绑定。

## 界面与构建边界

宿主构建目标是 Node.js 20，以兼容 VS Code 1.100.0；开发工具链使用 nvm 管理的 Node.js 24。esbuild 分别输出 `dist/extension.js`、`dist/webview/main.js` 和 `dist/webview/main.css`。React 随包构建，安装用户无需 npm 依赖或外部 Web 服务。

Webview 只允许读取其构建目录，脚本使用 nonce CSP，禁止直接网络连接。API 密钥在宿主管理的密码框内录入，Webview 仅接收元信息与密钥存在状态。详见[已实现的消息边界](./protocol.md)。

主页与任务详情由同一原生侧栏工作台承载，选择任务直接进入详情。详情使用紧凑模型栏、用户右侧／AI 左侧的聊天、独立证据面板和常驻输入框；宽窗口证据栏约 360 CSS 像素，低于 1100 CSS 像素时改为宽度不超过 430 CSS 像素及视口的抽屉。任务列表与操作允许换行，窄窗口设置和弹窗可以滚动，操作入口保持可见。颜色来自 VS Code 主题变量，两种语言共用组件及稳定角色 ID。

## 连接验证与模型查询

当前开发分支按[场景 6–7](./design.md)实现使用 Bearer 认证的 OpenAI 兼容端点。`src/providers/models.ts` 在已保存的 API 基础路径后追加 `/models`，保留网关路径前缀。本功能不包含 Azure 专用认证或推理协议。

用户明确发起查询 → 宿主在存储锁内读取连接元信息和密钥 → `ModelQueries` 在锁外执行网络请求 → 宿主返回校验后的 ID 和时间 → React 展示候选列表或手动输入。Webview 保留禁止直接联网的 CSP；查询不发送任务需求、角色指令或工作区内容。

每个连接最多有一个可取消的在途查询。适配器限制 20 秒超时、2 MiB 响应正文，校验结构并去重 ID；拒绝重定向，只返回本地化错误码，不转发上游错误正文。消息桥设有 30 秒兜底超时，同时关联请求 ID 与连接 ID。

结果只存在于 React 内存中，不持久化。成功修改地址／密钥或删除连接会取消请求并使缓存失效，迟到结果不能重新填充缓存。重命名、修改默认值或取消密钥输入保留列表。刷新不改写已选 ID、任务绑定或角色快照。默认模型允许为空，存储版本保持不变。

查询仅验证模型列表接口的访问权限。端点不支持、空列表或失败时仍可手动输入。已实现的消息契约见[通信协议](./protocol.md)。

## 开发分支的任务执行

宿主执行服务按工作区维护一个活动执行，不依赖 Webview 是否打开。服务固定任务／模型／角色／命令配置快照，调用 Git 任务目录服务，先由 Reviewer 规划，再驱动 Worker 自主实施与验证 → 附加检查 → Reviewer 验收或下发下一轮方案的循环。开始、暂停、继续、停止、重新执行和暂停时反馈独立于本地设置保存。完成要求验收项证据有效、附加检查成功、Reviewer 通过且成果指纹保持一致。

`src/providers/inference.ts` 分别适配流式 Chat Completions 和 Responses，保持独立角色历史与整批工具参数校验。文件写入仍只提供给 Worker；两个角色通过 `LocalCommands` 执行 shell 命令，Reviewer 在规划／答疑时探查，验收时可准备依赖、构建和测试。旧预设保持字面参数。shell 选择、每次运行的登录环境捕获和进程清理分别实现，见[通用 shell 执行](./shell-execution.md)。

执行摘要和命令配置使用独立工作区存储，公开事件日志保存在仓库之外，每次分页读取 80 条，UI 流式更新以 100 毫秒批量推送。宿主重启将未完成执行标记中断，不重放工具操作。API 凭据只存在于 SecretStorage 和活动宿主内存中，不进入历史、交接及命令输出。活动栏唯一视图 `dualMind.tasks` 使用 `WebviewViewProvider` 承载完整工作台；执行服务由宿主持有，视图销毁只释放页面通信和监听器。

模型请求总超时 120 秒、响应上限 8 MiB、序列化请求大小保护 512 KiB。独立角色的上下文预算与自动摘要见[生命周期说明](./task-lifecycle.md)。每角色每阶段最多 20 次业务模型往返，摘要不重置预算；公开执行历史上限 64 MiB。本阶段不包含原工作区自动应用、Git 自动提交／合并和多任务同时执行。

## 角色隔离：数据与执行边界

当前实现分别保存 Worker／Reviewer 模型绑定、工作区任务和任务专属 Reviewer 指令快照。存储测试覆盖同连接同模型绑定、跨任务与跨工作区编辑、预设变化，以及修改输入对象或返回快照对象的情况。模型查询集成测试检查已保存的任务需求、Reviewer 指令和工作区标识不会进入模型列表请求。用户级设置与按连接共享的模型列表缓存是有意共享的数据，均不属于对话历史。

开发分支现已组装实际模型请求和独立角色历史。Worker 使用固定执行指令，Reviewer 使用任务保存的角色快照；运行时测试捕获请求验证隔离，界面中的角色标签不能代替隔离证据。

执行按工作区、任务、执行实例和角色区分独立历史。连接 ID、模型 ID 不能作为会话身份，即使双方使用相同端点和模型也一样。执行开始时固定任务需求、验收条件、角色指令和配置快照。两者共享需求与验收条件，各自只使用自己的角色指令和历史；后续设置变化不改写进行中的执行。

Worker 交接当前成果和测试证据；Reviewer 返回审查结论、问题及修改要求。不复制对方完整会话、内部分析或无关工具记录。交接内容属于待处理数据，不能替换接收方角色指令。关联与取消约束见[角色交接边界](./protocol.md#角色交接边界)。执行记录独立于版本 1 任务保存，模型 ID 和模型列表缓存仍不能作为会话身份。

## Git 任务工作目录基础（开发分支）

专用分支模式下，`src/git/` 为首次执行提供按需调用的宿主服务：每个任务一个 `dualmind/<规范化任务名>-<任务短ID>` 分支，以及位于扩展工作区存储目录、源仓库之外的独立 worktree。`ExecutionService` 在首次模型请求前调用 `TaskWorkspaces.prepare()`；`Workbench.prepareTaskWorkspace()` 保留为宿主集成包装接口。打开设置、查询模型或保存任务不会准备任务目录。

专用分支首次准备要求 Git 2.25+、已信任且在仓库根目录打开的单文件夹工作区、有名称的分支、有效提交，可选的本地基点分支；源目录未提交修改保留且不复制。拒绝裸仓库、子模块、分离 HEAD 和多文件夹工作区；可将已有 linked worktree 作为源目录。首次准备固定基准提交，不复制被忽略文件或生成文件。已准备任务可在源分支变化或变脏后复用，保留任务文件。Git 准备服务不会切换源目录分支，也不自动提交、stash、fetch、合并、推送或安装依赖；后续 Worker 可按方案准备项目依赖。

独立宿主记录 `dualMind.git.workspaces.v1` 保存任务／仓库身份、源分支、基准提交、任务分支、目录和 `preparing`／`ready` 阶段。Git 创建前先记录意图；恢复时核验目录归属、分支、公共仓库和基准祖先关系。创建完成但最终记录写入失败时，可在核验一致后恢复。冲突、就绪目录缺失或带修改的部分检出均保留供人工检查。宿主按仓库及登记表串行准备；Git 分支／路径冲突也会阻止另一个进程覆盖已有工作。任务存储保持版本 1，不执行迁移。

宿主为 Worker 或 Reviewer 绑定文件接口。双方可列出／读取普通文件、查看状态及相对基准的已跟踪文件差异；新未跟踪文件通过状态、列表和读取接口查看。只有 Worker 获得 `writeFile`，可创建普通子目录。每次访问重新检查任务是否存在、工作区信任、仓库绑定和 worktree 归属。拒绝绝对路径、目录穿越、符号链接、硬链接文件和 Git 元数据访问。Git 不经过 shell，禁用钩子、外部 diff、textconv、内容过滤器和文件监视程序；不会下载或物化 LFS／过滤器生成内容。单个命令超时 20 秒、输出上限 2 MiB，单个文件读写上限 2 MiB；超过限制返回错误，不将截断内容作为审查证据。

这是工具接口权限边界，不是操作系统沙箱：能够直接访问文件系统的外部进程或用户仍可修改 worktree。Reviewer 通过独立命令能力探查和验证，文件写入／删除工具仍仅提供给 Worker；独立执行服务维护角色历史，[上下文约定](./protocol.md#角色交接边界)继续适用。

## 任务 Git 策略

任务可选 managed（默认专用）、current（当前分支）、branch（指定已有本地分支）。专用模式使用扩展存储中的独立 worktree，直接模式使用受信任的当前仓库。准备意图登记后策略锁定；current 在开始／重新执行时重新解析当前分支，branch 保留指定名称。直接模式的开始／重新执行检查干净状态，以目标 HEAD 固定基准；聊天中的继续修改使用已有绑定，复用未提交成果并重新取得验证证据，不重新准备或切换分支。同仓库准备串行，切换禁止猜测、覆盖忽略文件、钩子及过滤器，并保留其他 worktree 占用保护。

执行摘要保存完整 Git 绑定：策略、仓库及公共 Git 目录、工作目录、分支、基准及执行 HEAD。角色文件接口及命令边界验证该绑定。旧登记没有策略字段时按专用模式解释，保持基准复用，不迁移存储版本。预览及定位目录使用只读绑定查询，不调用准备服务。角色历史与 Reviewer 只读权限保持独立；目录仍不是操作系统沙箱，无法与任意外部进程的并发改动形成原子事务。

## Reviewer 规划与验收循环

执行服务按 preparing → planning → worker → checking（有附加检查时）→ reviewer 组织阶段。Reviewer 首先读取任务相关上下文，通过 submit_plan 输出需求理解、目标、步骤和验收项；Worker 接收方案而非 Reviewer 私有历史，通过文件工具与 run_command 落实方案，finish_work 只提交验收。Reviewer 的 submit_review 必须覆盖全部验收项，拒绝时携带完整 nextPlan；宿主为新方案递增版本，保存方案、交接和验收事件。角色快照保持兼容，各阶段系统指令明确规划、实施、验收职责。

方案由模型基于需求和相关文件形成，没有按语言或项目类型套用固定命令的自动检测器。Reviewer 保持文件只读；Worker 运行项目级依赖准备、探查和验证，不能通过角色交接获得 Reviewer 的完整会话或私有协议条目。用户反馈在 Reviewer 阶段处理，未处理的反馈阻止验收通过。

宿主记录命令真实参数、任务内相对目录、方案版本、轮次、退出状态、执行前后成果指纹及输出。完整脱敏输出写入分页事件，模型通过 read_command_output 分页读取，避免截断内容冒充完整证据。只有当前方案与成果版本一致、实际成功且关联对应验收项的验证记录才可通过；同项较新的失败使旧成功不能继续作为完成依据。附加自定义检查在每轮提交后必跑，旧配置默认启用。关闭时仍保存配置内容。

阅读审查必须有无需命令的原因和明确依据。无命令任务可独立完成。命令不依赖 systemd/cgroup，也不设置内存或交换空间配额；目录解析拒绝绝对路径、穿越和符号链接；外部进程仍以当前用户权限运行，目录检查不是操作系统沙箱。每阶段最多 20 次模型往返，命令与错误继续受输出、日志和脱敏限制。方案修改保留验收 ID 及验证方式，避免在修订中静默降低验收要求。

取消、超时、输出超限和父进程退出都会在后置指纹前清理进程。Linux／macOS 使用进程组，Windows 使用进程祖先、创建时间与系统进程树终止。无法确认清理时禁止新运行。具体限制和跟踪边界见[通用 shell 执行](./shell-execution.md#生命周期和验证)。

## 持续会话与执行边界

`RunRecords` 将用户消息和 Reviewer 答复追加保存到工作区扩展存储的 `conversations/<taskId>.jsonl`。状态更新复用消息 ID；同一 ID、不同内容拒绝。同一任务的方案、成果、审查和系统错误从原始运行 JSONL 兼容投影，旧文件不迁移，缺少角色的旧结论作为系统记录展示。聊天分页与证据分页独立，稳定 ID 去重；同一命令及流式请求的输出块在证据读取时合并。

`ExecutionService` 在活动任务的交接点读取待处理消息。`answering` 阶段允许 Reviewer 的读取工具、探查用途的 `run_command`、`submit_answer` 和 `submit_plan`；不提供写入、删除或验收工具。答疑使用 `kind: conversation` 和终态 `answered`，保持之前执行的验收状态；收到修改方案才转为 `kind: execution`。同一活动批次不重置轮次；空闲后的继续修改创建关联的新运行，并重新获得验证证据。

后续执行通过 `TaskWorkspaces.binding(taskId, previous.git)` 校验并复用目录，不调用会要求干净目录或切分支的 `prepare`。上一轮命令输出可以供 Reviewer 阅读，但不会导入当前有效证据集合。停止后的消息不自动启动；重载把处理中消息恢复为待处理并标记中断。消息、错误、答复与执行记录在写入和传输前脱敏。

`TaskChat.tsx` 管理聊天滚动、消息发送、独立分页和证据面板状态；模型信息使用紧凑栏。面板展开集合按事件 ID 保存，语言切换与更新不依靠重新挂载面板。视口断点控制右栏／抽屉，抽屉约束键盘焦点。首页、侧栏与详情忽略已结束的纯问答会话来选择最近一次真实执行状态。

## 原生 shell 命令

两个角色现共用[通用 shell 执行层](./shell-execution.md)，自动继承环境，并允许 Reviewer 独立验证，无需语言专用设置。已配置 macOS 和 Windows 原生 CI，须观察到实际通过后才能标记为已验证。历史验证报告保留当时范围。

## 活动元数据与兼容分支命名

活动操作通过可选 `ExecutionSnapshot.activity` 暴露运行／任务／角色／阶段、等待／接收／工具／命令状态、操作 ID 和开始时间。模型首个流事件才改变接收状态，不逐秒写日志。完成、异常、暂停和停止清除活动信息；它只存在于执行服务内存，重载不会恢复过期操作。聊天现已按[已审核界面](./chat-progress-proposal.md)显式启用公开过程投影。

新专用登记增加 `branchNaming: {version: 2, slug, suffixLength}`；缺少该字段时仍校验旧 UUID 格式。实际分支和命名元数据都与登记绑定核对。首次准备后名称固定，重名按任务 UUID 的 8／12／32 位依次尝试。工作区路径、直接分支策略及历史存储版本保持原有规则。

## 紧凑聊天展示

`ChatActivity` 读取临时活动并在前端计算耗时。`ChatCard` 将标题和图标按钮放在滚动正文外，宽屏正文上限 240 CSS 像素，低于 1100 像素窗口时为 180；完整展开只改变高度。系统记录最小化后保留错误标记。证据面板支持打开／最小化／关闭，桌面使用 44 像素窄条，窄屏从抽屉恢复。新记录／错误提示依据宿主完整证据历史的归并计数，不依赖最近 80 条事件。

带版本的 Webview 状态保存导航及各任务显示偏好、范围和证据滚动位置，兼容旧版纯导航并丢弃未知任务 ID／字段。公开过程使用稳定请求身份，较旧 sequence 不覆盖更新的内容。消息锚点避免流式更新和布局变化打断历史阅读，仅靠近底部时跟随新内容。隐藏内容保留 DOM，以保留记录展开状态；抽屉关闭恢复焦点。缩放按钮仅显示图标，同时提供悬停提示／无障碍名称；减少动画偏好会禁用旋转。

## 故障恢复

宿主现已保存角色、阶段、操作结果和执行位置，支持失败及重载后从原运行继续，使用当前模型连接并保持原方案、工作轮次和未提交文件。只读 `read_operation` 可读取旧操作；恢复不依赖最近 80 条界面事件。普通工具失败仍返回模型；尚未收到有效流事件的临时连接故障最多请求三次，含等待共用 120 秒预算。认证、额度和协议问题不自动重试。

带播放图标的**继续执行**可接续暂停及符合条件的失败／中断运行。固定恢复提示显示角色、阶段、保存位置和阻塞原因，证据面板最小化时仍可查看。恢复检查与可取消的重试等待使用宿主真实状态和请求次数，倒计时仅在界面更新。“重新执行”仍创建新运行。设计见[已审核恢复界面](./recovery-proposal.md)，日志、进程与证据限制见[恢复说明](./execution-recovery.md)。

## 原生侧栏生命周期

[原生侧栏工作台](./sidebar-workbench-proposal.md)场景 24–27 已于 **2026-11-22 审核通过**，2026-11-23 接入源码。完整工作台由主侧栏或辅助侧栏承载，提供紧凑导航、可折叠任务详情和手动“终端仅占编辑器区域”操作。旧页签仅用于迁移；现有 27 组审核记录和历史设计保留。
`src/core/viewChannel.ts` 为每个页面绑定握手、超时和回复。回调发送前检查页面身份；旧页面的迟到回复不能发送到新视图。初始化重试创建新的通道，显示时重发快照，聊天从分页日志补齐。`retainContextWhenHidden` 保留隐藏页面；重新创建时通过 Webview state 和工作区显示状态副本恢复导航及聊天偏好。

`src/shared/viewState.ts` 只接收白名单显示字段，优先顺序为当前侧栏、本地工作区副本、旧页签。`view.state` 镜像显示偏好；`rendered` 在状态保存成功后完成握手。旧 `dualMind.workbench` 序列化回调启动迁移但不等待渲染，避免 VS Code 恢复死锁；迁移失败保留原页签和重试入口。`navigation.ack` 防止重复消费新建任务请求。协议与运行记录格式未更改。

`dualMind.alignPanelCenter` 仅在手动调用时执行 VS Code 原生面板居中命令，不保存或重置侧栏位置。前端维持任务聊天实例以保留切换设置时的草稿和阅读位置；任务详情展开状态纳入已有任务显示偏好。
