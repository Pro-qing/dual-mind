## 已实现的本地工作台

`dualMind.openWorkbench` 创建或定位一个 React Webview 面板，面板渲染宿主快照后命令才完成；序列化恢复逻辑在窗口重载后重新打开面板。`dualMind.showStatus` 保留为本地化的就绪提示。命令、监听和面板随扩展生命周期释放。

宿主拥有本地状态并校验所有输入操作；React 管理页面导航、表单缓冲、弹窗和独立的只读示例预览。界面不发起模型请求，保存任务会创建草稿，不创建运行中的智能体会话。

## 状态归属

| 状态                                               | 存储与行为                                                                              |
| -------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 草稿与选中任务                                     | `ExtensionContext.workspaceState`，键为 `dualMind.local.workspace.v1`，要求已打开工作区 |
| 连接、模型默认值、自定义角色和内置角色分语言覆盖值 | `ExtensionContext.globalState`，键为 `dualMind.local.global.v1`                         |
| API 密钥                                           | `ExtensionContext.secrets`，以连接 ID 关联，不进入界面快照                              |
| 语言选择                                           | 用户设置 `dualMind.language`：`auto`、`zh-CN`、`en`                                     |
| 选中页面                                           | Webview 状态，重载后可恢复                                                              |
| 未保存表单、弹窗和示例预览                         | React 内存；示例不会进入任务存储                                                        |

存储层在同一宿主内串行处理写入，避免快速操作丢失状态；检查已存数据的版本和结构，发现不受支持的数据时报告错误，不覆盖原数据。持久化成功后宿主确认操作，并返回新快照；保存失败时保留表单供重试。

创建任务会保存一个 Reviewer 角色的名称、用途、指令和语言快照，编辑已有草稿仍保留该快照。内置角色覆盖值按语言独立保存，自定义内容标记为 `original`，不会自动翻译。Worker 始终是固定通用执行角色。删除角色不影响快照；删除连接会移除其密钥、清除对应默认值，并保留引用它的草稿供重新绑定。

## 界面与构建边界

宿主构建目标是 Node.js 20，以兼容 VS Code 1.100.0；开发工具链使用 nvm 管理的 Node.js 24。esbuild 分别输出 `dist/extension.js`、`dist/webview/main.js` 和 `dist/webview/main.css`。React 随包构建，安装用户无需 npm 依赖或外部 Web 服务。

Webview 只允许读取其构建目录，脚本使用 nonce CSP，禁止直接网络连接。API 密钥在宿主管理的密码框内录入，Webview 仅接收元信息与密钥存在状态。详见[已实现的消息边界](./protocol.md)。

宽度低于 1200 CSS 像素时折叠任务侧栏，低于 900 像素时对话上下排列。窄窗口设置和弹窗可以滚动，操作入口保持可见。颜色来自 VS Code 主题变量，两种语言共用组件及稳定角色 ID。

## 连接验证与模型查询

当前开发分支按[场景 6–7](./design.md)实现使用 Bearer 认证的 OpenAI 兼容端点。`src/providers/models.ts` 在已保存的 API 基础路径后追加 `/models`，保留网关路径前缀。本功能不包含 Azure 专用认证或推理协议。

用户明确发起查询 → 宿主在存储锁内读取连接元信息和密钥 → `ModelQueries` 在锁外执行网络请求 → 宿主返回校验后的 ID 和时间 → React 展示候选列表或手动输入。Webview 保留禁止直接联网的 CSP；查询不发送任务需求、角色指令或工作区内容。

每个连接最多有一个可取消的在途查询。适配器限制 20 秒超时、2 MiB 响应正文，校验结构并去重 ID；拒绝重定向，只返回本地化错误码，不转发上游错误正文。消息桥设有 30 秒兜底超时，同时关联请求 ID 与连接 ID。

结果只存在于 React 内存中，不持久化。成功修改地址／密钥或删除连接会取消请求并使缓存失效，迟到结果不能重新填充缓存。重命名、修改默认值或取消密钥输入保留列表。刷新不改写已选 ID、草稿绑定或角色快照。默认模型允许为空，存储版本保持不变。

查询仅验证模型列表接口的访问权限。端点不支持、空列表或失败时仍可手动输入。已实现的消息契约见[通信协议](./protocol.md)。

## 开发分支的任务执行

宿主执行服务按工作区维护一个活动执行，不依赖 Webview 是否打开。服务固定任务／模型／角色／命令配置快照，调用 Git 任务目录服务，执行准备命令，再驱动 Worker → 必跑检查 → Reviewer 的轮次循环。开始、暂停、继续、停止、重新执行和暂停时反馈独立于本地设置保存。完成要求检查成功、Reviewer 通过且成果指纹保持一致。

`src/providers/inference.ts` 分别适配流式 Chat Completions 和 Responses，不自动切换协议或重试。工具参数完整接收并校验后才执行，每个角色维护自己的协议历史；Responses 推理条目只保留在所属角色内部。文件工具按角色授权，写入采用原子替换，Reviewer 没有命令或写入工具。检查命令以固定预设 ID 调用，在受资源限制的用户 systemd 单元中运行，不接受模型指定的 shell 字符串。

执行摘要和命令配置使用独立工作区存储，公开事件日志保存在仓库之外，每次分页读取 80 条，UI 流式更新以 100 毫秒批量推送。宿主重启将未完成执行标记中断，不重放工具操作。API 凭据只存在于 SecretStorage 和活动宿主内存中，不进入历史、交接及命令输出。活动栏 Tree View 订阅同一宿主状态并打开单例工作台。

模型请求总超时 120 秒、响应上限 8 MiB、请求上下文上限 512 KiB。每角色每轮最多 20 次模型往返，公开执行历史上限 64 MiB，超限明确失败。本阶段不包含原工作区自动应用、Git 自动提交／合并和多任务同时执行。

## 角色隔离：数据与执行边界

当前实现分别保存 Worker／Reviewer 模型绑定、工作区草稿和任务专属 Reviewer 指令快照。存储测试覆盖同连接同模型绑定、跨任务与跨工作区编辑、预设变化，以及修改输入对象或返回快照对象的情况。模型查询集成测试检查已保存的任务需求、Reviewer 指令和工作区标识不会进入模型列表请求。用户级设置与按连接共享的模型列表缓存是有意共享的数据，均不属于对话历史。

开发分支现已组装实际模型请求和独立角色历史。Worker 使用固定执行指令，Reviewer 使用任务保存的角色快照；运行时测试捕获请求验证隔离，不以双栏界面代替证据。

执行按工作区、任务、执行实例和角色区分独立历史。连接 ID、模型 ID 不能作为会话身份，即使双方使用相同端点和模型也一样。执行开始时固定任务需求、验收条件、角色指令和配置快照。两者共享需求与验收条件，各自只使用自己的角色指令和历史；后续设置变化不改写进行中的执行。

Worker 交接当前成果和测试证据；Reviewer 返回审查结论、问题及修改要求。不复制对方完整会话、内部分析或无关工具记录。交接内容属于待处理数据，不能替换接收方角色指令。关联与取消约束见[角色交接边界](./protocol.md#角色交接边界)。执行记录独立于版本 1 草稿保存，模型 ID 和模型列表缓存仍不能作为会话身份。

## Git 任务工作目录基础（开发分支）

专用分支模式下，`src/git/` 为首次执行提供按需调用的宿主服务：每个任务一个 `dualmind/task/<任务 UUID>/worker` 分支，以及位于扩展工作区存储目录、源仓库之外的独立 worktree。`ExecutionService` 在首次模型请求前调用 `TaskWorkspaces.prepare()`；`Workbench.prepareTaskWorkspace()` 保留为宿主集成包装接口。打开设置、查询模型或保存草稿不会准备任务目录。

专用分支首次准备要求 Git 2.25+、已信任且在仓库根目录打开的单文件夹工作区、有名称的分支、有效提交，以及干净的源工作目录（包括已暂存、未暂存和未忽略的未跟踪文件）。拒绝裸仓库、子模块、分离 HEAD 和多文件夹工作区；可将已有 linked worktree 作为源目录。首次准备固定基准提交，不复制被忽略文件或生成文件。已准备任务可在源分支变化或变脏后复用，保留任务文件。不会切换源目录分支，也不自动提交、stash、fetch、合并、推送或安装依赖。

独立宿主记录 `dualMind.git.workspaces.v1` 保存任务／仓库身份、源分支、基准提交、任务分支、目录和 `preparing`／`ready` 阶段。Git 创建前先记录意图；恢复时核验目录归属、分支、公共仓库和基准祖先关系。创建完成但最终记录写入失败时，可在核验一致后恢复。冲突、就绪目录缺失或带修改的部分检出均保留供人工检查。宿主按仓库及登记表串行准备；Git 分支／路径冲突也会阻止另一个进程覆盖已有工作。草稿存储保持版本 1，不执行迁移。

宿主为 Worker 或 Reviewer 绑定文件接口。双方可列出／读取普通文件、查看状态及相对基准的已跟踪文件差异；新未跟踪文件通过状态、列表和读取接口查看。只有 Worker 获得 `writeFile`，可创建普通子目录。每次访问重新检查任务是否存在、工作区信任、仓库绑定和 worktree 归属。拒绝绝对路径、目录穿越、符号链接、硬链接文件和 Git 元数据访问。Git 不经过 shell，禁用钩子、外部 diff、textconv、内容过滤器和文件监视程序；不会下载或物化 LFS／过滤器生成内容。单个命令超时 20 秒、输出上限 2 MiB，单个文件读写上限 2 MiB；超过限制返回错误，不将截断内容作为审查证据。

这是工具接口权限边界，不是操作系统沙箱：能够直接访问文件系统的外部进程或用户仍可修改 worktree。Reviewer 无法通过该接口运行测试或任意命令，由 Worker 执行并交接测试证据；独立执行服务维护角色历史，[上下文约定](./protocol.md#角色交接边界)继续适用。

## 任务 Git 策略

任务可选 managed（默认专用）、current（当前分支）、branch（指定已有本地分支）。专用模式使用扩展存储中的独立 worktree，直接模式使用受信任的当前仓库。准备意图登记后策略锁定；current 每次执行重新解析当前分支，branch 保留指定名称。直接模式每次执行都检查干净状态，以目标 HEAD 固定基准。同仓库准备串行，切换禁止猜测、覆盖忽略文件、钩子及过滤器，并保留其他 worktree 占用保护。

执行摘要保存完整 Git 绑定：策略、仓库及公共 Git 目录、工作目录、分支、基准及执行 HEAD。角色文件接口及命令边界验证该绑定。旧登记没有策略字段时按专用模式解释，保持基准复用，不迁移存储版本。预览及定位目录使用只读绑定查询，不调用准备服务。角色历史与 Reviewer 只读权限保持独立；目录仍不是操作系统沙箱，无法与任意外部进程的并发改动形成原子事务。
