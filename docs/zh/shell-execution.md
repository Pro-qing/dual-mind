# 通用 shell 执行与独立验证

[English](../en/shell-execution.md) · [使用说明](./usage.md)

Worker 和 Reviewer 在 Linux、macOS、Windows 上共用宿主管理的 `run_command`，无需语言专用环境设置或预先保存命令。本次源码新增 macOS 和 Windows 原生 CI，只有实际任务通过后才能标为已验证；保留 Ubuntu 20.04 基线。

## 环境和命令

每次运行固定扩展宿主环境，并以五秒执行期限探测一次登录环境。Unix 优先使用用户配置的 Bash/Zsh，否则 Linux 使用 Bash、macOS 使用 Zsh，最后回退 `sh`。Windows 优先 PowerShell 7，其次 Windows PowerShell，最后 `cmd`。Unix 读取登录启动文件，PowerShell 加载 profile。只捕获导出的环境变量，不保留别名、函数或 shell 会话状态。探测错误或超时回退宿主环境，并向模型说明；取消会停止运行，清理无法确认时不会回退继续。

每条命令从该快照启动新的 shell。将初始化和操作放在同一次调用，例如 Bash 中的 `. .venv/bin/activate && python -m pytest` 或 `. /opt/ros/jazzy/setup.bash && colcon test`；PowerShell 使用对应的激活和调用语法。前一次 `cd`、`export` 和激活不持续。模型会获知实际平台、shell、任务目录和降级状态。代理可安装项目依赖、创建虚拟环境；缺少 Node.js、Python、编译器等基础工具链时应报告，不安装用户级／系统级工具链或提权。

环境原始值只保留在宿主内存，不自动写入提示词、事件或历史。敏感名称对应的环境值加入连接密钥脱敏，覆盖跨流式分块的输出。连接密钥不会额外注入命令环境；用户原本导出的凭据仍会继承，因此本地命令能够访问它们。命令使用当前用户权限，不是操作系统沙箱，也不保证任意命令无害。捕获后移除 `BASH_ENV`、`ENV` 等启动钩子，需要时在命令内显式初始化。

`run_command` 接收 `name`、`command`、`purpose`、`criterionIds`，以及可选相对 `cwd` 和 `timeoutSeconds`。默认超时 180 秒，范围 10–900 秒，合并输出上限 2 MiB。管道、重定向和多行脚本遵循实际 shell 语义。PowerShell 使用 UTF-8，后续 cmdlet 成功也不会掩盖此前原生命令的失败退出码；自行选择输出编码的 Windows 工具仍可能需要编码参数。已有 `program`／`args` 预设保持字面参数执行，必须指向可执行程序，不拼接为 shell 文本。shell 内建命令和 Windows 批处理使用通用 shell 工具。

## 角色和证据

Worker 实施方案并验证修改。Reviewer 在规划和答疑阶段可探查，验收阶段还可准备项目依赖、构建和测试。Reviewer 没有文件写入／删除工具，提示词禁止通过命令主动修改源码，但 shell 仍拥有当前用户权限。审查期间文件变化使提交指纹失效，触发现有暂停与重新验证流程，保留实际文件。

宿主记录命令的实际角色和阶段、原始 shell 命令（脱敏后）、shell、目录、用途、验收项、方案版本、执行前后指纹和结果。尚无方案时版本为 0，不能用于验收。Reviewer 可引用自己成功验证的 ID，无需预先出现在 Worker 提交中。证据必须匹配当前方案、验收项及未变化的成果指纹，退出码为零且没有失败原因。同一验收项后续失败会使旧成功失效。没有角色字段的旧记录继续按 Worker 解释，不重写历史。

## 生命周期和验证

取消、超时、输出超限和父进程正常退出都会在记录后置指纹前清理残留进程。Unix 使用进程组，先 SIGTERM，三秒后仍存活则 SIGKILL，最多十秒确认；Linux 检查 `/proc`，macOS 使用 `ps`，僵尸进程不算运行中。Windows 跟踪进程祖先与创建时间，通过 `taskkill /T /F` 清理，再查询确认，清理预算十五秒。无法确认停止会锁住当前宿主的新运行。这些机制不是进程隔离：主动脱离 Unix 进程组的服务，以及中间祖先进程在两次观测间消失的 Windows 后代，可能逃离跟踪。不要启动需要跨命令长期存活的后台服务。

原生测试覆盖 shell 语法、中文路径、环境快照、退出码、限制、取消和遗留子进程。协议集成测试覆盖两种模型协议、Reviewer 探查及独立验证、审查测试失败、源码变化、旧预设与历史证据。Linux 在本地验证，CI 新增 macOS／Windows 的完整检查、扩展宿主测试和打包。执行仍要求受信任的单个本地文件工作区，不扩展 Remote SSH／WSL 支持结论。

## 故障恢复

宿主现已保存角色、阶段、操作结果和执行位置，支持失败及重载后从原运行继续，使用当前模型连接并保持原方案、工作轮次和未提交文件。只读 `read_operation` 可读取旧操作；恢复不依赖最近 80 条界面事件。普通工具失败仍返回模型；尚未收到有效流事件的临时连接故障最多请求三次，含等待共用 120 秒预算。认证、额度和协议问题不自动重试。

带播放图标的**继续执行**可接续暂停及符合条件的失败／中断运行。固定恢复提示显示角色、阶段、保存位置和阻塞原因，证据面板最小化时仍可查看。恢复检查与可取消的重试等待使用宿主真实状态和请求次数，倒计时仅在界面更新。“重新执行”仍创建新运行。设计见[已审核恢复界面](./recovery-proposal.md)，日志、进程与证据限制见[恢复说明](./execution-recovery.md)。

## 内置常用命令

Linux x64 的 `rg`、`fd`、`jq` 随 VSIX 离线提供；系统优先，仅追加任务进程 PATH。构建前显式运行 `npm run tools:fetch`，缓存完整后构建可离线进行。版本、失败行为、许可与验证见 [内置常用命令](./bundled-tools.md)。
