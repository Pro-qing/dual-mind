## 主页、任务详情与错误信息

工作台默认进入任务主页。点击任务进入独立详情；点击“新建任务”并创建成功后，立即打开新任务详情，状态为“待执行”。创建不会启动模型请求。配置未齐仍可创建，详情会列出缺少的连接、密钥、模型；补齐后点击“开始”。编辑和保存直接作用于任务，没有单独的草稿提交步骤。

详情中的“返回主页”不停止执行。从详情打开设置后可返回原任务；VS Code 侧栏点击任务也进入对应详情。重载恢复当前页面与任务；目标已删除时回到主页。删除当前任务后返回主页，执行中的任务仍须先确认停止。

应用产生的错误随界面语言显示，包括运行失败、检查命令错误、Git 操作、模型请求和桥接超时。必要时展开“原始详情”查看脱敏后的原文；外部命令输出和模型回答不自动翻译。旧历史错误保留原文，并提供本地化说明。切换语言会更新结构化错误的提示。

**已归档的本地源码修订：**主页任务行仅显示名称和删除图标，点击名称进入详情；长名称单行省略，悬停可查看全文。顶部数量继续保留，需求、角色、分支、轮次和逐项状态在详情中查看。删除先确认，活动任务使用“停止并删除”；示例中的名称可打开详情，删除与页面新建按钮禁用。对应[场景 28–29](./task-home-compact-proposal.md)已审核并接入，此说明不表示已有标签或安装包已包含修改。

## 运行要求

支持基线为 **Ubuntu 20.04+、x86_64/amd64、VS Code 1.100.0+**。其他平台和 ARM64 暂未验证。从 Marketplace 或已构建的 VSIX 安装均无需另行安装 Node.js，详见[环境说明](./environment.md)。

## 打开工作台

点击活动栏 DualMind 图标，或运行 **DualMind: 打开工作台**（英文编辑器为 **DualMind: Open Workbench**），进入完整原生侧栏工作台。默认使用主侧栏；重复打开会定位已有视图。原生标题栏的 **＋** 创建任务，首页打开已保存任务；任务顶部的返回和设置按钮负责页面导航。**DualMind: 显示状态**保留为就绪检查。创建任务前先打开文件夹或工作区；未打开工作区时仍可浏览设置和只读示例。

右键活动栏的 DualMind 图标，选择 **移动到 → 辅助侧栏**，或拖动容器，更改 DualMind 的位置。位置和宽度由 VS Code 保存；重新打开不会强制移回左侧。侧栏全高指标题栏和状态栏之间的工作区。

在视图更多菜单或命令面板手动运行 **DualMind: 终端仅占编辑器区域**，将底部面板设为居中。此时打开或调整终端高度不会挤占左右侧栏；如果改成跨窗口对齐，VS Code 仍可能压缩侧栏高度。DualMind 只在点击该命令时调整布局。

隐藏、折叠、移动侧栏或切换设置不会停止运行。重新显示会补齐快照和持久化聊天；消息展开及输出最小化偏好按任务保留。旧编辑器页签在升级时迁移导航和聊天偏好，已有侧栏显示状态优先；侧栏就绪且显示状态保存成功后关闭旧页签。初始化失败时旧页签提供重试按钮。迁移不传递凭据或执行上下文。

任务详情默认收起分支、轮次、模型及编辑操作，点击 **任务详情与操作** 展开。状态和主要运行控制保持可见。聊天使用剩余高度，输入框在底部；代码和长消息可内部滚动。设置使用单列正文和类别选择器，语言选择在设置页顶部。极矮窗口允许内容滚动以保留操作入口。

## 本地任务

首次打开显示空任务列表。创建任务前先打开文件夹或工作区。**新建任务**需要名称、需求和恰好一个 Reviewer 角色，保存该角色的指令快照，默认五轮，并允许为 Worker 与 Reviewer 分别选择连接和模型。API 未配齐也可以**创建任务**。

选择已保存的任务可查看需求和角色快照。**编辑任务**更新文本、模型绑定及轮次上限，原有角色指令保持固定。删除需确认，仅移除任务记录，保留工作区文件、其他任务和角色预设。

任务与选中任务按工作区保存，重新打开工作台或重载窗口后恢复。不同工作区拥有独立任务列表。未打开工作区时仍可使用设置和示例。

**查看示例**展示只读任务／对话及预期并行任务外观，**退出示例**返回真实任务。示例不写入记录，也不发起模型请求。

## API 设置

以下查询功能适用于从源码构建的当前开发分支。已发布的 `0.0.1`／Preview 2 安装包保留原有的本地设置能力。

设置 → **API 连接**管理名称、HTTP(S) Base URL 和可选的默认模型 ID。新连接预填 `https://api.openai.com/v1`，也可填写兼容服务的 API 基础路径。首次配置顺序如下：

1. 保存名称和 Base URL，默认模型可以留空。
2. 点击**设置密钥**，在原生 VS Code 密码框中输入密钥。页面只收到保存状态。
3. 点击**测试并获取模型**。**模型列表可访问**仅确认列表接口可访问，不代表推理权限或聊天适用性已验证。
4. 搜索或选择模型 ID，也可手动输入自定义 ID，然后**保存连接**。**刷新模型**不会改变当前模型值。

打开设置或选择器不会自动请求。各连接的列表独立，仅在当前工作台挂载期间缓存。查询展示加载中、成功及数量／时间、空列表或本地化错误；失败或端点不支持列表时仍可手动输入 ID。修改 Base URL 后先保存再查询；成功修改地址／密钥或删除连接会使旧列表失效，取消替换密钥则保留旧密钥和列表。

设置 → **新任务的默认配置**在设置类别选择器中有独立入口。在此配置 Worker／Reviewer 绑定，并点击**保存默认值**。切换类别会丢弃未保存的修改；重载恢复当前类别及已保存的值。连接自身的默认模型仍在“API 连接”页管理。

Worker 与 Reviewer 的默认绑定相互独立，新任务继承默认值；已有任务保留保存过的 ID，即使新列表中没有该 ID。表单主动切换连接时使用该连接的默认模型，允许为空。方向键导航候选项，Enter 选择，Escape 优先关闭列表，再关闭任务弹窗。鼠标选择后关闭菜单并保留输入焦点。

连接元信息、默认值和角色预设属于本机 VS Code 用户，可跨工作区使用。删除连接会移除密钥并清除对应默认绑定；引用它的任务仍可编辑。凭据保存在 VS Code 秘密存储中，查询不发送任务需求或工作区内容。

## 语言与 Reviewer 定义

使用**设置 → 界面语言**，或 VS Code 的 `dualMind.language` 设置：

| 值             | 行为                                              |
| -------------- | ------------------------------------------------- |
| `auto`（默认） | 中文 VS Code 显示简体中文，其他编辑器语言显示英文 |
| `zh-CN`        | 简体中文                                          |
| `en`           | English                                           |

手动选择按用户保存并立即生效。工作台标签、提示、校验、确认框和示例内容跟随切换。原生命令名称和设置说明跟随 VS Code 自身的显示语言。

设置 → **Reviewer 角色**提供 Bug、Feature、Review、Refactor。每类分别维护英文和简体中文的用途／指令，内置名称固定并本地化。编辑或恢复只影响当前显示语言，恢复默认需要确认。Worker 保持通用执行职责。

自定义角色的名称、用途和指令保持录入时的原文，支持新增、编辑和删除。创建任务时保存选定预设及语言的快照；之后切换语言、修改或删除预设，都不追改已有任务。因此中文界面中可能保留英文任务快照，反之亦然。

通过语言选择器切换时，普通表单保留已输入内容。若角色指令有未保存修改，会先提供**保存**、**放弃修改**和**取消**；保存会先写入当前语言版本。离开页面或重载窗口前，请明确保存表单。

## 执行任务（开发分支）

点击活动栏 **DualMind 图标**，打开工作台并创建任务。创建成功进入详情，任务为“待执行”；首次执行须由用户点击“开始”启动模型请求。

1. 配置 Worker 和 Reviewer 的连接、密钥及模型，选择对应的 Chat Completions 或 Responses 协议。模型需要支持流式响应和工具调用。
2. 打开可信任的单根 Git 仓库，确保有已提交的命名分支；直接模式要求目录干净，隔离模式允许原目录有未提交修改且不会复制这些修改。选择专用 worktree、当前分支或指定本地分支。
3. 写清需求并点击“开始”。**Reviewer 先阅读相关项目内容，拆解需求，下发执行方案和验收条件。** 初始规划不计入执行轮数。
4. **Worker 按方案执行**，按需准备项目依赖、修改文件并选择具体命令进行验证。无需在设置中手填准备或检查命令；Worker 不自动安装系统工具链。
5. Worker 提交成果、真实执行证据及未解决问题，**Reviewer 查看实际文件和差异，逐项验收**。通过则完成；未通过必须下发下一轮执行方案，Worker 自动继续，直到通过、达到轮次上限或用户停止。

详情展示当前方案版本、步骤、验收项、成果提交及结论，历史保留各轮方案和真实命令记录。命令结果包含退出状态、输出和证据 ID；代码修改后必须重新验证，失败或过期证据不能算通过。纯文档等任务可采用阅读审查，明确记录无需命令的原因与检查依据。验收通过不自动提交、合并或推送。

暂停在当前操作边界生效；运行中或暂停时均可通过聊天提交消息，Reviewer 在角色交接处理；发送不会自动恢复暂停。继续恢复执行，停止取消请求和命令。每轮为 Worker 执行加 Reviewer 验收；达到上限仍未通过时保留剩余问题。重载将未完成运行标记为中断，重新执行创建新的运行记录并重新规划。运行／暂停中的任务及引用的关键连接配置保持锁定；删除活动任务先停止，保留 Git 成果。

### 高级设置：附加自定义命令

**设置 → 任务执行**默认说明双 AI 流程。展开**高级设置**并启用**附加自定义命令**，可增加用户要求的准备或检查步骤：准备在方案形成后、Worker 开始前执行；附加检查在每轮提交后全部运行并且必须通过。Worker 仍可补充必要验证。

每条命令填写名称、程序、逐行参数以及 10–900 秒超时，默认 180 秒。例如程序 `npm`、参数分别填写 `run` 和 `check`，表示 `npm run check`。程序和参数分别传递，不隐式解析 shell 字符串。关闭开关保留命令内容；已有非空旧配置默认启用，旧空配置默认关闭。修改设置只影响后续运行。

命令在任务目录或其普通子目录中以当前用户身份直接运行，不依赖用户级 systemd 或 cgroup v2，扩展不设置内存和交换空间配额。默认超时 180 秒（可选 10–900 秒），输出上限 2 MiB。取消、超时或输出超限时终止整个命令进程组；主进程正常退出也会清理同组遗留子进程，再生成成果指纹。无法确认停止时记录错误，并阻止当前宿主继续启动任务。这不是操作系统沙箱，主动脱离进程组的后台服务不在该清理范围内。API 密钥不注入命令环境，日志和交接内容脱敏。独立 worktree 不复制被忽略的依赖目录，Worker 根据项目实际条件准备依赖；缺少程序或权限时提供双语说明和原始详情，不自动安装系统工具链。

## 开发分支选择（开发版本）

新任务默认“使用 DualMind 专用分支”，继续使用独立 worktree。“使用当前分支”在开始／重新执行时确定当前分支，直接修改打开的项目；“使用指定本地分支”从已有本地分支中选择，开始前切换到该分支。刷新列表和保存任务均不切分支；直接模式不自动建分支或拉取远程分支。

直接模式每次开始／重新执行都要求目录干净，包括暂存、未暂存和未忽略的未跟踪文件。请自行提交或处理上次成果。目标被其他 worktree 占用、忽略文件冲突或包含子模块时拒绝切换。准备意图登记后策略锁定，如需改变请新建任务；旧任务保持专用模式。

直接模式会修改当前项目，停止、完成或删除任务都不会撤销修改、自动切回原分支。“定位当前项目文件”聚焦资源管理器；差异预览只读取该次执行固定的目录、分支和 HEAD，不切换分支。直接模式开始／重新执行采用目标 HEAD 作为新基准；聊天续接验证并复用已有绑定和未提交成果，不重置基准。专用模式保留原基准和成果。运行中切分支或改变 HEAD 会阻断后续操作。Reviewer 不得主动修改源码，但可独立执行探查与验证命令。已发布 0.0.1 制品行为不变。

[协议说明中的 worktree 人工清理方式](./protocol.md#内部-git-工作目录服务)仅适用于专用模式，不能用于删除直接模式下用户打开的项目。

## 任务聊天、追问与继续修改

任务详情采用紧凑模型栏、主聊天区、右侧证据面板和常驻输入框。用户消息在右侧，Reviewer 方案／验收／答复和 Worker 成果在左侧；系统错误单独标记。原始需求仅在聊天开头展示，角色预设说明不再占据大卡片。宽窗口显示约 360 像素证据栏，视口不足 1100 CSS 像素时使用可关闭抽屉，支持 Escape、键盘焦点约束和关闭后恢复焦点。

点击消息的“查看执行详情”打开截至该消息的执行记录，重复点击只定位，不收起面板。“查看全部记录”解除范围；工具、过程输出和命令详情独立展开，原始命令输出局部滚动。聊天与证据分别加载更早记录；阅读历史时保留位置，并以“有新消息”提示新增内容。

创建任务仍需手动“开始”。开始前发送的消息先保存。运行后直接在底部输入问题或修改要求：Enter 发送，Shift+Enter 换行，中文输入法组合输入不会误发。保存成功才清空输入；失败保留输入，重试复用消息 ID。

- 解释和澄清：Reviewer 可以读取任务文件，通过 `submit_answer` 回复，不调用 Worker 或命令，也不改变上次真实验收结论。答复显示“已回复”。
- 继续修改：Reviewer 检查当前成果并制定方案，随后自动进入 Worker／Reviewer 循环。新执行关联上一次执行与触发消息，轮次按任务配置重新计算。
- 执行中补充：消息立即保存为“待处理”，当前操作继续；Reviewer 在角色交接或最终完成前处理。问题不消耗修订轮次，修改须形成新方案，当前批次仍受原轮次上限约束。
- 暂停、停止与重载：发送消息不会恢复手动暂停。停止保留未处理消息，可显式继续处理；失败或重载中断时，宿主要求先恢复原运行（点击“继续执行”），不会通过消息处理入口另起运行。其他任务活动时，消息可以保存，处理仍遵守单活动任务限制。

继续修改支持专用 worktree、当前分支和指定分支，复用绑定目录及未提交成果。用户额外编辑会纳入当前文件和差异；新成果必须取得新证据。继续前检查目录归属、分支和 HEAD，变化时保留消息并报错，不切分支、重置、提交或清理文件。“重新执行”保留原来的重新准备语义，直接模式仍检查工作区干净，与聊天中的继续修改不同。

## 原生 shell 命令

两个角色现共用[通用 shell 执行层](./shell-execution.md)，自动继承环境，并允许 Reviewer 独立验证，无需语言专用设置。已配置 macOS 和 Windows 原生 CI，须观察到实际通过后才能标记为已验证。历史验证报告保留当时范围。

## 任务名分支与紧凑聊天控件

新建专用工作区采用 `dualmind/<任务名>-<短ID>`，支持中文任务名。名称规范化、冲突与旧分支保留规则见[提案](./chat-progress-proposal.md#新分支规则后端已实现)。准备后修改任务标题不会重命名分支；当前／指定已有分支模式继续使用所选分支。

活动条显示当前角色、操作和耗时，模型没有正文时也会显示等待。公开过程与方案／验收分别标识。每条消息有图标式缩放按钮：短消息自然显示，长消息在最高 240 像素正文内滚动（窄屏 180），点击向外箭头可完整展开，字号不变；悬停可见操作名称。系统消息和证据记录可最小化，保留错误标记。面板减号在宽屏留下 44 像素窄条，在窄屏留下工具栏恢复入口；新记录／错误只更新提示，不强制展开。手动选择在任务切换、语言切换和 Webview 重载后保留，只改变当前任务的显示，不停止执行。

## 故障恢复

宿主现已保存角色、阶段、操作结果和执行位置，支持失败及重载后从原运行继续，使用当前模型连接并保持原方案、工作轮次和未提交文件。只读 `read_operation` 可读取旧操作；恢复不依赖最近 80 条界面事件。普通工具失败仍返回模型；尚未收到有效流事件的临时连接故障最多请求三次，含等待共用 120 秒预算。认证、额度和协议问题不自动重试。

带播放图标的**继续执行**可接续暂停及符合条件的失败／中断运行。固定恢复提示显示角色、阶段、保存位置和阻塞原因，证据面板最小化时仍可查看。恢复检查与可取消的重试等待使用宿主真实状态和请求次数，倒计时仅在界面更新。“重新执行”仍创建新运行。设计见[已审核恢复界面](./recovery-proposal.md)，日志、进程与证据限制见[恢复说明](./execution-recovery.md)。

## 新增生命周期页面

设置类别新增“模型上下文”和“保存的成果”。前者按连接／模型保存窗口覆盖，留空回到默认估算；后者列出保存清单、排除目录、来源与恢复标识，可恢复为新任务。原工作区没有 Git 仓库时，成果页面说明限制，连接设置仍可使用。

新建隔离任务可选择基点分支，默认在准备时解析当前分支。任务详情中的“模型上下文用量”与“任务成果”可展开；成果面板提供刷新预览、提交、普通合并、冲突检查／完成／中止、清理和后续任务入口。提交说明可编辑；切换合入目标须刷新预览，合入时核对捕获的目标提交。冲突完成／中止确认显示实际合并目录与目标提交。直接模式不提供清理原目录的操作。

删除确认默认仅删除记录，可勾选同时保存清理；活动任务须先停止，再确认新的预览。清理后聊天与证据保持只读，输入区提供后续任务及快照恢复。恢复成功后打开新任务详情，等待用户手动开始。操作超时先检查状态，再沿用同一操作 ID 重试。

工具失败、跳过、拒绝和未知结果分别显示。第三次无进展错误暂停后，可添加反馈并继续；历史错误数与当前验收阻塞分开显示。详见[工具错误说明](./tool-errors.md)。

## 内置常用命令

Linux x64 的 `rg`、`fd`、`jq` 随 VSIX 离线提供；系统优先，仅追加任务进程 PATH。构建前显式运行 `npm run tools:fetch`，缓存完整后构建可离线进行。版本、失败行为、许可与验证见 [内置常用命令](./bundled-tools.md)。
