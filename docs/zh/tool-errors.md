# 工具错误、暂停与验收

[English](../en/tool-errors.md) · [界面记录](./tool-errors-proposal.md) · [任务生命周期](./task-lifecycle.md)

**2026-11-23 已归档的本地修订，版本仍为 0.0.5。** 本轮确认了现有前端设计，并授权工具错误处理与前端一起接入。场景 28–34 已接入，场景 35–37 按确认方案同步制作及实现，不另设视觉审批停点。历史标签及发布记录保持原样。

## 三层结果

普通工具失败先反馈给当前 Worker／Reviewer，不立即切换角色，也不自动重跑失败命令。工具结果区分 `succeeded`、`failed`、`rejected`、`skipped`、`cancelled`、`unknown`；另以 `execution` 区分未开始、已执行及副作用未知。命令 `ok` 继续表示命令成功，与工具是否正常返回、任务是否通过验收分别判断。

工具结果含调用 ID、宿主操作 ID、请求 ID、错误及关联命令／跳过原因。大结果缩为片段时保留状态、退出信息和操作引用，全文可通过 `read_operation` 获取。命令分别记录 stdout、stderr、耗时、退出码及终止原因，合并输出仍可查看；旧记录没有的字段不伪造。输出共用现有 2 MiB 采集预算。宿主先脱敏；当合并输出含敏感内容时，独立通道保守隐藏并指向脱敏后的合并输出，避免跨通道密钥碎片重新暴露。

## 批次与权限

参数、未知工具、角色不可用或结束工具顺序不合法时，宿主整批拒绝执行，为各调用返回诊断和当前可用工具。传输层仍拒绝不完整流、缺失／重复调用 ID。执行中首个普通工具或命令失败后，剩余调用（包括结束工具）标记未执行，并指出前序失败操作；已完成调用和文件修改不回滚。宿主独立附加检查继续收集全部配置检查的结果。

文件不存在、路径错误、普通权限错误、命令启动失败、非零退出，以及已确认终止的超时／输出超限属于可纠正结果。信任撤销、绑定变化、持久化失败、进程退出无法确认或用户停止会中断推进。已开始但结果不明的操作保持未知，不声称没有发生副作用。取消或旧代次回复不能推进新运行。

## 重复失败与预算

同角色、同阶段、同工具及有效参数、相同错误／退出原因和工作区指纹构成失败身份，命令展示名称不计入。第三次无进展重复失败暂停；无关只读诊断不清除计数。相同调用成功或参数／相关状态改变后，新的失败重新计数。连续三批预检失败同样暂停。

暂停原因、计数和批次结果进入恢复记录。用户可查看失败、补充反馈并明确继续；继续只开启新纠错观察窗口，不清零总预算。每阶段最多 20 次业务模型往返及 200 次工具调用；已接纳批次的拒绝和跳过调用也计数，超出剩余预算的整批不执行。摘要、重载和恢复不重置总预算，也不重放完成的工具操作。

复合命令仍遵循所选 shell 的原语义，不注入 `set -e` 或 pipefail，不自动拆分子命令或推测其退出码。默认超时 180 秒，允许 10–900 秒。模型可根据明确结果调整工具、参数或任务方案。

## 验收与界面

正式验收继续核对当前方案、验收项、文件指纹、附加检查及最新证据。历史探查失败不永久阻止完成；最新验证失败、跳过、未知或过期结果不能作为通过证据。Worker 可在后续请求中提交真实失败与未解决事项，由 Reviewer 下发修复方案。

证据界面按宿主操作关联工具卡和命令结果，同一次失败只计一次；跳过项显示原因而不冒充执行失败。历史失败数与当前验收阻塞分开显示，零错误或工具结束不代表任务验收通过。暂停原因在窄窗口及证据面板最小化时仍可见。

模型上下文、工作树基点、提交／普通合并、冲突处理、清理与保存成果入口一并接入，详见[生命周期说明](./task-lifecycle.md)。确认操作使用预览令牌和稳定操作 ID；超时先重新检查，重载显示待完成操作，派生任务在宿主快照包含任务后打开。

验证采用单核、低优先级、串行分批，监测测试进程树内存、换页、主机可用内存和超时。实际结果记录在[开发日志](./development-log.md)，静态图稿不代替真实界面验证。
